# ADR-0015：推演与判官模型（Jev / Laya）

- 状态：已接受（推演生成待门禁通过后启用）
- 日期：2026-10
- 决策者：sqhc

## 背景

项目的差异点不是「把今天的新闻念一遍」，而是**基于已收集数据推演事件的后续影响**。
这需要一个能给出**校准概率**的模型，而不是又一段听起来合理的文字。

候选是 TypeSafe 的 Jev（托管）与其开源同类 Laya（可本地部署）。

## 决策

1. **判官是与 LLM 平行的第二类客户端**，不是 `LlmClient` 的实现。
   Jev/Laya 不生成文本，只回答「在给定候选项上怎么打分」。措辞可以来自模板或 LLM，
   **概率只能来自判官**。这条边界让「概率是不是模型真给的」永远可查。
2. **本地 Laya**（multilingual checkpoint）为零样本默认，云端 Jev 保留为可切换分支。
   两者共用一套请求协议（本地 `serve.py` 暴露 Jev 兼容的 `/v1/systemone`），**只差 base_url**。
3. **概率不能直接发布**。必须通过评估门（`make eval-judgement`）才允许在视频/页面上
   把链路称作「推演」；未过门时强制标注「未经校准」。

## 评估结果（为什么门禁是必要的）

三条独立证据说明**不能把 Laya 零样本概率当预测用**：

| 实验 | 结果 |
| --- | --- |
| 覆盖预测（7 天，247 样本，锁定测试集） | Brier 技能分 **-1.69**，ECE **0.36**（门槛 skill>0.05、ECE<0.15） |
| 同一实验 + Platt 校准 | ECE 降到 **0.07**（修好了校准），但拟合斜率 **0.0199**——校准器几乎完全忽略模型输入，只预测基率；技能分仍为 **-0.028**（历史实验，当时产物未存档，见下文说明） |
| 措辞对照（coverage vs progress） | 差异落在噪声内（-0.028 vs -0.044，n=127） |

可靠性曲线显示的具体失败模式：模型说「约 8% 会发生」的那批实际 94% 发生了。

**只报 ECE 会把第二次实验误判成通过**——两个指标必须一起看。

## 但同一个模型做分类是可用的

在**人工别名表**（31 组、274 对、人工逐条核对）上评估实体对齐：

| | 校准集 133 对 | 锁定测试集 141 对 |
| --- | --- | --- |
| AUC（阈值无关） | 0.799 | **0.796** |
| 阈值（校准集选出） | 0.406 | 沿用 |
| F1 | 0.887 | **0.882** |
| 精确率 / 召回率 | 0.797 / 1.000 | 0.812 / 0.964 |
| 多数类基线 | 0.767 | 0.794 |

结论：**排序能力真实，绝对分数不可当概率用**。准确率（0.794）几乎等于多数类基线（0.794），
只看准确率会误判成「没信号」；F1 与 AUC 才说明有真实判别力。

## 踩过的两个坑

1. **阈值不能写死成量表中点。** 最初用 1.5，实测召回率 0.009、精确率 1.000，
   看起来像「模型完全不行」。实际是判官**从不使用最高档位**（正样本档位分布 0/1/2 = 16/198/0），
   分数挤在 0.3–1.4。正确做法：用 AUC 衡量排序，阈值只在校准集上选。
2. **不要用错误的阈值做二次过滤。** `pairs_to_merge` 曾用 `decide()`（中点阈值 1.5）
   二次过滤路由器已批准的结果，会静默丢掉绝大多数合并。单元测试抓到了这个 bug。

## 后果

- **簇不能做纵向评估**：实测 702 个簇跨度中位数 **0 天**（聚类按 24 小时窗口合并同期报道），
  推演的时间单元必须是**实体/话题**。
- 已登记预测（`predictions` 表）开始积累真实到期核对样本；
  这是将来做领域微调（教程第十章 RLCD/LoRA）的**标签来源**。
- **微调不排期（已定案）**：理由从「样本不够」升级为「问题口径下无信号可学」——
  2026-10-15 复测确认两代判官（Laya 322M / 云端 Jev）在同一口径上 AUC 都≈0.5，
  微调练的是概率质量，没有信号就不是「等样本」能解决的（见下节与「云端 Jev 复测」节）。
  **不要把「样本在积累」误读成「等下去就能做微调」。**

## 后续实验：为什么「等样本攒够再微调」是错的

原计划是「先等 P3 攒够已标注样本，再做领域微调」。为此做了两个决定性实验
（`make tune-judgement`，`backend/app/eval/experiment.py`）。
（注：本表为 2026-10-15 之前的历史实验，**当时产物未存档**、.cache 已被后续
运行覆盖，无法逐数复现；复现需在同一数据库快照上重跑 `make tune-judgement`。
本章其余 2026-10-15 实验的产物已存 `docs/evidence/`。）

| 实验（7 天 horizon，锁定测试集 n=145） | coverage 措辞 | progress 措辞 |
| --- | --- | --- |
| 原始 Brier 技能分 | -1.167 | -0.825 |
| 原始 AUC | 0.601 | **0.574** |
| Platt 校准后技能分 | -0.012 | -0.005 |
| Platt 校准后 ECE | 0.067 | **0.027** |
| Platt 拟合斜率 | **-0.026** | **-0.004** |

两个结论：

1. **换措辞救不了。** coverage 与 progress 都失败，差异在噪声内。
2. **Platt 校准的「改善」是假象。** 斜率是**负的**——校准器几乎完全忽略模型输入，
   只输出常数（基率 0.779），于是 Brier 自然回到基率、skill 趋近 0、ECE 看起来很漂亮。
   这不是「校准好了」，而是**把模型信息全部丢掉**。
   单看 skill=-0.005 会被误读成「只差一点就过门」。

因此 `metrics.roc_auc` 被加为**强制伴随指标**：AUC 0.574（0.5=随机）
说明排序能力最多是弱的，platt 无法修复没有的信息。
代码现在会在 AUC<0.55 时明确报「没有区分能力，攒样本/重拟合都不会改善，
只能换判官或换问题」——把「不可用」和「接近可用」在报告层面区分开。

**这是对 ADR-0015 待办的修正**：P4 微调不是「等时间」，而是「当前问题口径下不可解」。
要推进只能：换云端 Jev、或设计一个真正可预测的客观标签口径（例如「事件是否在
N 天内被至少 M 个新来源报道」这类更机械的目标）。

### 结果一：概率门仍未通过，AUC≈随机

7 天 coverage 口径，与 Laya 基线同一评估器。**样本量不同**：Laya 零样本基线
n=60（`docs/evidence/eval-judgement-laya.json`，基率 0.85），Jev n=200
（`docs/evidence/eval-judgement-jev.json`，基率 0.80）——样本量差 3 倍多，两列数字
不可直接当同精度对比读；结论（双双未过门、Jev AUC≈0.5）不受影响。

| | Laya 零样本（n=60） | Jev（jev-1.13.0，n=200） |
| --- | --- | --- |
| 基率 | 0.85 | 0.80 |
| Brier / 常数基线 | — | 0.218 / 0.160 |
| Brier 技能分 | -1.69 | **-0.362** |
| ECE | 0.36 | 0.193 |
| AUC | — | **0.528**（n=200，SE≈0.03-0.04，与 0.5 不可区分） |

措辞对照（n=300，锁定测试集 145）：coverage / progress 原始 skill 分别为
-0.079 / -0.254，Platt 校准后 -0.014 / -0.013、ECE 0.091 / 0.052——
与 Laya 相同的失败模式：ECE 修好看但 skill 仍为负，模型输入没有真正进校准器。

**结论：瓶颈在问题口径，不在模型强度。** 本地 322M 的 Laya 与云端更强的
Jev 在同一口径上同样失败（AUC≈0.5），说明「该实体 7 天内是否再被报道」
在现有语料特征下接近不可预测。「换更强的判官」这条歧路就此封死，
要推进只剩：**重新设计一个真正可预测的客观标签口径**（人的决策）。

### 结果二：分类能力跨模型成立，且 Jev 显著更强

同一套人工别名表金标准（31 组、274 对，两 provider 同 n，可直接对比）：

| | Laya | Jev（jev-1.13.0） |
| --- | --- | --- |
| AUC（阈值无关） | **0.799** | **1.000** |
| 名义阈值 1.5 下 acc（基线 0.781） | 0.219（**阈值假象**，见下） | 0.956 |
| 校准阈值 / 锁定集 F1 | 0.406 / **0.882** | 0.560 / **1.000** |

**阈值假象注（2026-10-15 晚修正，勿删）**：本表初稿曾把 Laya 写成
「acc 0.226 ❌ 低于基线」并得出「Laya 分类不可用」——这是错的，且是**双重**
评估口径问题：①`eval-alignment` 只用写死的名义中点阈值 1.5（`ALIGNMENT_THRESHOLD`）
出二分类指标，而判官几乎不用最高档位（见「踩过的坑」第 1 条），Laya 的分数挤在
低档，名义阈值下几乎全判「不同」；同模块的 `roc_auc / choose_threshold /
split_pairs` 早已实现却从未被该命令调用。②`16b5383` 之前的版本还把每边最近
报道标题塞进 prompt（context 污染），会让 Laya 的排序反转——
**两个数字各归一项**：`acc 0.226` 属 ①（名义阈值假象，带不带 context 都≈0.22），
`AUC 0.232` 属 ②（带 context 的旧口径 AUC）——两者**均已作废**
（证据：`docs/evidence/eval-alignment-laya-ctx.json`、60 对诊断见
`docs/evidence/README-context.md`）。生产口径（不带 context、按模型校准阈值）
的真实数字是 **AUC 0.799（274 对全量）/ F1 0.882 / recall 0.964**（锁定测试集口径为
AUC 0.796——`alignment-split.json` 的 auc_all / auc_test，两者都对，别当成不一致；
与最早一次评估精确复现）。
**正确表述：Laya 分类可用、需阈值校准（名义阈值下原始 acc 仅 0.219——
不是模型不行，是默认阈值不匹配它的分数分布）；Jev 原始量表即可用且近乎完美
（精确率 1.0 / 0 误合并）。**「跨模型规律」指的是分工方向（分类可用/概率不可用），
不是两边能力数字可以直接互换。

**教训（本项目第二个「看着像模型不行、其实是评估实现问题」的案例）**：
评估实现（塞不塞 context）与阈值口径（名义中点 vs 校准阈值）都能**翻转结论**——
第一个案例是本章「踩过的坑」第 1 条（阈值写死量表中点，召回 0.009 看起来像
模型完全不行）。凡下「某判官不可用」的结论，先核对：指标是阈值无关的吗？
prompt 是否与生产路径一致？

「判官做分类、不做概率」从 Laya 的实测教训**升级为跨模型规律**：
两个独立模型给出同一分工结论，这是该类判官的架构边界，不是实现的偶然。

### 对决策的修正

1. `projection_enabled` 保持 `false`；「未经校准」标注不摘。
2. P4（领域微调）**不排期**：微调练的是概率质量，两代模型 AUC 都≈0.5，无信号可学。
3. 云端 Jev 的生产价值**只用于分类**（实体别名裁决 / 一键采纳）。key 10-22 到期后
   SDK 异常被包成 `JudgementError`：简报降级为不出推演（不崩），分类回落 Laya——
   Laya 回退后**仍可用但变弱**（AUC 0.799 / F1 0.882，需沿用校准阈值 0.406，
   不是不可用，见结果二的阈值假象注）。
4. 如实随报告走的两条局限：对齐金标准样本小（正样本几十对、负样本 60 对），
   负样本是「不同国家的常见实体」（较容易），未覆盖「同名不同实体」困难场景；
   概率评估只覆盖「事件是否继续发展」客观子问题，语义节点无客观标签仍未验证。
5. 基础设施同步落地：`calibration_summary` 按 provider 分开统计
   （`dc163b1`，Laya/Jev 样本不混算）、`make doctor` 加判官连通性检查
   （`8e4a927`，key 到期提前暴露）、`.env.example` 记录推荐配置（`82b5da2`）。

### 三条写死的判读（防止后人误读）

**① 校准统计口径已修（`dc163b1`）。** 此前 `calibration_summary` 不分 provider
一把全捞：Laya 期与 Jev 期登记的预测先后到期后，`GET /predictions/calibration`
的 Brier/ECE 会把两代判官混成一条曲线——违反诚实性约束。修复后支持
`?provider=jev` 过滤、返回 `by_provider` 分布；合并口径真的混了多个判官时
显式给 `mixed_providers` 并提示「这些数字不对应任何一个模型」。
`resolve_due` 也不再覆写 `model` 列（登记时模型保留，核对方另存
`evidence.resolved_by`）。**按 provider/model 分组统计是硬要求，不是可选项。**

**② AUC 0.528 < 0.55 ⇒「本质不可用」分支：不做校准、不指望攒样本。**
评估器（`eval/judgement.py:353`）把未过门分成两档：无区分能力（AUC<0.55）
与有排序信号但概率不可用。Jev 落在前者——**skill≈0 时做 Platt 是自欺**
（校准器只会退化成常数基率，ECE 修好看是假象，本文 Platt 实验已两次证明），
攒样本也不会改变结论。`projection_enabled` 保持 false，「未经校准」不摘。

**③ P3 预测登记的定位：留「可被证伪的失败记录」，不是通往过门。**
登记继续跑，但它攒的不是「将来微调或校准的原料」（那条路已随 P4 一起否决），
而是对每期推演留下一份带概率、带到期时间、可被事后核对的行为记录——
它证明的是「我们登记过什么、后来发生了什么」。别把「样本在积累」误读成
「再等等就能过门」。

- 判官当前的生产用途是**实体别名裁决**（分类）：实测人工正例自动合并率 97.7%、零误合并。
  （2026-10-15 复测后说明：该用途当前由 Jev 承担——原始量表即可用、0 误合并；
  Laya 需校准阈值 0.406 也能胜任，见修订节的阈值假象注。初稿曾据
  「Laya acc 0.226」误判其不可用，已在下文修正。）

## 修订 2026-10-15（晚）：对齐评估口径修正 + 推荐配置决策

### 对齐结论的修正：0.226 是评估口径的假象，Laya 排序能力一直都在

当天晚些时候发现两个评估口径问题，都会独立地把 Laya 误判成「不可用」：

1. **名义阈值假象**（`5670eb3` 修复）：`eval-alignment` 只用写死的阈值 1.5 出
   二分类指标——正是本文「踩过的坑」第 1 条在同一命令里的复发：判官把三档压到
   低档后，名义阈值下 Laya 几乎全判「不同」（acc 0.226 / recall 0.009），
   而 `roc_auc / choose_threshold / split_pairs` 早已实现却从未被该命令使用。
2. **context 污染**（`16b5383` 修复）：旧版本把每边最近报道标题塞进 prompt，
   会让 Laya 的排序反转——AUC 0.809 → 0.172（负样本均值反超正样本）。
   生产路径 `alias_adjudication.py` 本来就只按名称提问：上一轮「Laya 0.226 不可用」
   的结论测的是提示写法的副作用，不是模型能力。数字与复现步骤存档在
   `docs/evidence/README-context.md`：60 对诊断 0.809 → 0.172（负样本均值
   0.606 → 1.178），274 对全量带 context 对照 0.232
   （`docs/evidence/eval-alignment-laya-ctx.json`）——该口径产物**全部作废**。

修正后重跑（同一金标准 274 对，不带 context，锁定测试集）：

| | Laya | Jev（jev-1.13.0） |
| --- | --- | --- |
| AUC（阈值无关） | 0.799 | **1.000** |
| 名义阈值 acc（基线 0.781） | 0.219（假象，见上） | 0.956 |
| 校准阈值 / 锁定集 F1 | 0.406 / **0.882** | 0.560 / **1.000** |

**分工结论不变、强度刷新**：Jev 分类近乎完美（AUC 1.000 / F1 1.000）；
Laya 恢复其本来的 0.799 / 0.882（与最早一次评估精确复现）。
上一节表格中的「Laya acc 0.226 ❌」按此修正：那是名义阈值假象，
不是模型判别力缺失——ADR 里保留错误数字与修正过程，防止下轮再踩。

**修正连锁影响**：上一节第 3 条「到期回退后分类≈不可用」作废——
Laya 回退后别名裁决**仍可用**（AUC 0.799 / F1 0.882），只是弱于 Jev；
`.env.example` 的回退说明已同步更正。

### 推荐配置（用户 2026-10-15 拍板）

key 有效期内，判官推荐配置为**云端 Jev**：
`JUDGEMENT_PROVIDER=jev` + `JUDGEMENT_BASE_URL=https://api.typesafe.ai` +
`JUDGEMENT_MODEL=jev-latest`（已写入 `.env.example` 注释，`82b5da2`）。
理由：实体对齐 Jev 接近完美（AUC 1.000），Laya 可用但明显更弱（AUC 0.799）——
推荐 Jev 是为了分类质量，不是为了替换掉一个不能用的模型；概率两边都未过门，
切换不改变概率侧结论；
成本实测每期简报 ≤9 次调用 ≈ 1.3 万输入 token（TypeSafe 牌价不足一美分，可忽略）。
