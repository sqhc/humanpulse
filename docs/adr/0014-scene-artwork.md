# ADR-0014：分镜视觉程序化生成（不使用原文配图）

- 状态：已接受
- 日期：2026-10
- 决策者：sqhc

## 背景

ADR-0010/0013 交付的视频简报，所有镜头都是**纯文字卡片**（深色底 + 居中文字）。
「每镜配图」是当时列的待办。最直觉的做法是抓取原文的 og:image 当配图。

## 决策

**不抓取、不合成任何第三方图片。** 背景由我们自己程序化生成（app/video/artwork.py）。

理由不是技术限制，而是**政策冲突**：ADR-0002 定的是「只存元数据、短引用与 AI 摘要，
不对外提供全文」。把出版方的图片下载下来、合成进我们自己的视频再分发：

1. 直接违反这条政策；
2. 授权无法逐张核对（同一篇文章的配图可能来自第三方图库）；
3. 视频是**再分发**行为，比在网页上显示缩略图的风险更高。

所以「配图」在这里被重新定义为「视觉设计」，而不是「引用图片」。

## 实现

| 元素 | 做法 | 为什么 |
| --- | --- | --- |
| 底色 | 按分镜类型着色的竖直渐变 | 观众对「现在看的是哪一类」有直觉 |
| 底纹 | 右下角同心圆弧（透明度 6-26） | 纯色卡太素；圆弧不抢字 |
| 水印 | 标题（不超过 16 字）或专有名词 | 提供上下文，且**保证是完整词** |
| 主色条 | 左上角细条 | 呼应站点强调色 |

**确定性**：配色与选词只依赖文本，同一分镜每次渲染出的图完全一致。

### 两个踩过的坑（都已修，并有回归测试）

1. **中文不做分词。** 最初用 CJK 贪婪切分（2-6 字），产出过「南非枪击案造」这种半个句子当水印，
   看起来像乱码。现在中文只允许**标题**做水印（标题本来就是完整短语），
   英文只取专有名词与较长的词。
2. **英文折行按词不按字符。** wrap_text 原本逐字符折行，成片里出现过
   「commande / r in Gaza strike.」——单词被劈开，像排版坏了。
   现在先切成「不可再分的单元」（CJK 一字一个，拉丁整词一个）再贪心装行。

## 后果

- 视频观感从「PPT」变成「有设计的图文卡」，仍然不需要任何外部素材或授权。
- 代价是**画面与内容没有视觉关联**（不是那条新闻的照片）。这是政策约束下的取舍，
  不是实现偷懒；将来要配图，正确路径是接入**有明确授权**的图库（如 Wikimedia Commons）。
- artwork.py 的纯函数（配色、选词、折行）与画图分离，CI 不装 Pillow 也能测——
  已用「阻断 PIL 导入」验证过五个视频模块都能在无 Pillow 环境下 import。
