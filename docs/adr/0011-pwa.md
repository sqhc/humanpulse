# ADR-0011：可安装的 Web 应用（PWA）

- 状态：已接受
- 日期：2026-10
- 决策者：sqhc

## 背景

平台计划里有「移动端」。客户端选项有三条：

1. 原生 / Expo / Dioxus：体验最好，但要维护第二套代码、签名、发版流程；
2. 包装成 Tauri 桌面 + 移动：仍在路线图里，但同样带来打包与发布成本；
3. PWA：同一套 React 代码，加清单与 Service Worker，浏览器即可「添加到主屏」。

当前只有一个开发者、部署还是单机 VPS，投入产出比最高的是第 3 条。

## 决策

1. **先做 PWA**：`web/public/manifest.webmanifest` + 两个尺寸图标（192 / 512，512 声明 maskable），
   `display: standalone`，`theme_color` 与站点深色底一致。
2. **Service Worker 手写，不引入 vite-plugin-pwa**。它只做一件事：缓存**应用外壳**，
   规则简单到可以直接读代码审计；Web 插件会带来一套构建期配置，而这里只需要一条策略。
3. **接口数据一律不缓存**。`/api/**` 直接 `return`（不 respondWith），导航请求网络优先、
   断网才回退到缓存的外壳。理由：这是一份新闻类数据，**过期的旧数据比没有数据更危险**，
   用户会对「看到的是不是最新的」失去信心。
4. **只在生产构建注册**（`import.meta.env.PROD`）。开发时 Vite 每次重新编译模块，
   SW 缓存会让改动「看不见」；注册失败（http 访问、隐私模式）只告警，不影响应用可用性。
5. **移动体验靠响应式 + 可安装**，暂不做离线写、后台同步、推送通知。

## 后果

- 离线时只能看到**外壳与已缓存的静态资源**，看不到数据（会显示接口错误态）——这是第 3 条的代价，
  刻意如此。
- Service Worker 有版本生命周期：改了缓存策略要改 `SHELL_CACHE` 名（当前 `humanpulse-shell-v1`），
  否则旧缓存会一直命中。
- 没有推送通知，所以「有突发事件」不会主动提醒；这需要 VAPID 密钥与后端推送链路，
  在移动端需求明确后再做。
- 桌面端与移动端共用同一套构建产物，`make dev-web` 出来的仍是普通网页（SW 不注册）。

## 验证

- `web/src/lib/pwa.test.ts`：开发环境不注册、生产注册 `/sw.js`、不支持时不报错、注册失败只告警；
- `web/src/lib/manifest.test.ts`：清单字段齐全、图标尺寸覆盖 192/512、图标文件真实存在；
- `make verify` 会跑前端构建，产物里包含清单、SW 与图标。
